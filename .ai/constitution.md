# 项目开发宪法

# Version: 1.0, Ratified: 2025-10-20

# Version: 2.0, Adapted: 2026-03-26

本文件定义了本项目不可动摇的核心开发原则。所有AI Agent在进行技术规划和代码实现时，必须无条件遵循。

---

## 第一条：简单性原则 (Simplicity First)

**核心：** 遵循"少即是多"哲学。绝不进行不必要的抽象，绝不引入非必需的依赖。

- **1.1 (YAGNI):** 你不需要它（You Ain't Gonna Need It）。只实现需求中明确要求的功能，不做未来扩展的预判。
- **1.2 (原生优先):** 除非有极其充分的理由，否则必须优先使用 JavaScript 原生能力。例如，数组操作优先用 `map/filter/reduce` 而不是 lodash；HTTP 请求优先用原生 `fetch` 而不是 axios。
- **1.3 (反过度工程):** 避免复杂的设计模式和过度抽象。简单的函数和数据结构优于复杂的继承体系和装饰器模式。
- **1.4 (依赖克制):** 引入新依赖前必须三思。优先评估：能否用原生 API 替代？是否值得增加包体积和维护成本？

---

## 第二条：测试先行铁律 (Test-First Imperative) - 不可协商

**核心：** 所有新功能或 Bug 修复，都必须从编写一个（或多个）失败的测试开始。

- **2.1 (TDD循环):** 严格遵循"Red-Green-Refactor"（编写失败测试-让测试通过-重构）的循环。
- **2.2 (表格驱动):** 单元测试必须优先采用表格驱动测试（Table-Driven Tests）的风格，以覆盖多种输入和边界情况。
- **2.3 (拒绝Mocks):** 优先编写集成测试，使用真实的依赖或 fake object（如内存中的 Mock Service Worker），而不是过度依赖 Mock。

---

## 第三条：明确性原则 (Clarity and Explicitness)

**核心：** 代码的首要目的是让人类易于理解，其次才是让机器执行。

- **3.1 (错误处理):** **不可协商**：所有错误都必须被显式处理。优先使用明确的错误类型（`Error`、`TypeError`、`RangeError`）或自定义错误类，绝不使用裸露的 `throw new Error()` 而不附带上下文信息。
- **3.2 (类型安全):** 在 TypeScript 项目中，必须为所有公共 API 标注类型。禁止使用 `any`，除非经过显式审查并记录原因。
- **3.3 (无隐式状态):** 绝不允许使用隐式全局状态。所有状态必须通过函数参数、React Context 或状态管理库显式传递。
- **3.4 (注释的意义):** 注释应该解释"为什么"，而不是"是什么"。所有公共 API 都必须有清晰的 JSDoc 注释。

---

## 第四条：单一职责原则 (Single Responsibility)

**核心：** 每个模块、每个文件、每个函数都应该只做好一件事。

- **4.1 (目录的内聚):** `src/` 目录下的各子目录应保持高度内聚和低耦合。例如，`data-constructor/` 只负责数据结构的实现，绝不能包含 UI 逻辑。
- **4.2 (接口隔离):** 定义小的、目标明确的类型和函数签名，而不是大而全的"上帝类型"。函数参数不超过 3 个，超出时应使用配置对象。
- **4.3 (纯函数):** 优先编写纯函数——相同的输入永远产生相同的输出，不产生副作用。

---

## 治理 (Governance)

本宪法具有最高优先级，其效力高于 `AGENTS.md` 中与本宪法相抵触的内容，并高于单次会话中的临时指令。任何计划（`plan.md`）在生成时，都必须首先进行"合宪性审查"。
