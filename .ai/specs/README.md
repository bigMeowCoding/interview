# `.ai/specs/` 规格文档

存放可验收的功能/课程/模块规格说明（与实现代码对应的「契约」或教学大纲）。

## 文件命名规则

必须使用 **`YYYY-MM-DD-`** 前缀（四位年、两位月、两位日的 **ISO 8601** 日历日期，与你的「年-月-日」一致），后跟 **kebab-case** 可读主题，后缀固定为 **`.spec.md`**。

| 片段 | 要求 |
|------|------|
| 日期前缀 | `YYYY-MM-DD-`，与原规范首次可验收或可合并入库的基准日对齐 |
| 主题 slug | 小写，`[-a-z0-9]+`，英语或拼音均可，语义清晰即可 |
| 后缀 | `.spec.md` |

**示例**：`2026-05-16-chrome-memory-leak-course.spec.md`

同一主题发生重大改版（验收范围显著变化）、且需要保留旧版对照时：使用**新版本对应的日期前缀**新建文件，旧的带日期前缀规格保留勿删改名中的日期含义；一般不推荐去掉旧文件的唯一日期前缀。

## 与本仓库源码

实现侧引用规格路径时须写完整文件名（含日期前缀）；新增规格后顺手更新讲义、Demo 正文中的链接字符串。
